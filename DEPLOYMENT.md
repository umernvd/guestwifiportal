# Deployment Guide — Facebook Follower-Gated WiFi Portal

## Prerequisites

- Node.js 18+ (for native `fetch` support)
- A Vercel account (for hosting the Next.js app)
- Omada controller with External Portal / Hotspot API enabled
- A Facebook Page (for the "Follow us" flow)
- Cloudflare Tunnel (`cloudflared`) or ngrok (optional — needed only if Vercel must reach your local relay)

---

## 1. Environment Variables

Set these in `.env.local` (at the project root) or in your Vercel Dashboard:

### `.env.local` (Vercel-side)

| Variable | Default | Description |
|----------|---------|-------------|
| `META_PAGE_ACCESS_TOKEN` | `mock` | Facebook Graph API access token. `mock` works with `MOCK_FOLLOWERS=true`. |
| `META_PAGE_ID` | `mock` | Facebook Page ID. `mock` works with `MOCK_FOLLOWERS=true`. |
| `MOCK_FOLLOWERS` | `true` | `true` = bypass Facebook (returns 150). `false` = real Graph API call. |
| `RELAY_URL` | `http://localhost:3001` | URL of your running relay. Use Cloudflare Tunnel URL for Vercel. |
| `RELAY_API_KEY` | `test123` | Shared secret. Must match `local-relay/.env`. |
| `NEXT_PUBLIC_FACEBOOK_PAGE_URL` | `https://facebook.com/yourpage` | Public URL shown to users in the portal. |

### `local-relay/.env` (Relay-side)

| Variable | Default | Description |
|----------|---------|-------------|
| `MOCK_OMADA` | `true` | `true` = bypass Omada (returns success immediately). `false` = real Omada calls. |
| `RELAY_API_KEY` | `test123` | Shared secret. Must match `.env.local`. |
| `OMADA_API_BASE` | *(empty)* | Full base path: `https://{IP}:{PORT}/{CONTROLLER_ID}/api/v2/hotspot`. Only needed if `MOCK_OMADA=false`. |
| `OMADA_USERNAME` | *(empty)* | Omada hotspot operator username. Only needed if `MOCK_OMADA=false`. |
| `OMADA_PASSWORD` | *(empty)* | Omada hotspot operator password. Only needed if `MOCK_OMADA=false`. |
| `PORT` | `3001` | Port the relay listens on. |

## 2. Running Locally

### Terminal 1 — Start the relay

```bash
cd local-relay
npm start
```

The relay starts on `http://localhost:3001`. By default it runs in mock mode (`MOCK_OMADA=true`) and returns success without calling Omada.

### Terminal 2 — Start the Next.js app

```bash
npm run dev
```

The portal is now available at `http://localhost:3000`.

### Test the portal directly

Open this URL in your browser (it simulates what Omada would redirect):

```
http://localhost:3000/portal?clientMac=AA:BB:CC:DD:EE:FF&apMac=11:22:33:44:55:66&ssid=GuestWiFi&site=MainOffice&redirectUrl=https://google.com
```

## 3. Mock Modes (Testing Without Real Services)

Both mocks are enabled by default so you can test the full flow without real credentials.

### `MOCK_FOLLOWERS=true` (bypasses Facebook)

- Located in `.env.local`
- When `true`, the fan-count API returns `{ count: 150 }`, which passes the threshold check (`150 > 0 + 1`)
- Clicking "I have followed! Check my access" will succeed and trigger the Omada relay
- **To disable**: set `MOCK_FOLLOWERS=false` and provide a real `META_PAGE_ACCESS_TOKEN` and `META_PAGE_ID`

### `MOCK_OMADA=true` (bypasses Omada)

- Located in `local-relay/.env`
- When `true`, the relay returns `{ success: true, mock: true }` immediately without calling the Omada controller
- The session transitions through `VERIFIED → AUTHORIZING → AUTHORIZED` as if Omada authorized it
- **To disable**: set `MOCK_OMADA=false` and provide real `OMADA_API_BASE`, `OMADA_USERNAME`, `OMADA_PASSWORD`

## 4. Cloudflare Tunnel (Production Only)

When deploying to Vercel, the relay must be publicly reachable. Expose it with Cloudflare Tunnel:

```bash
cloudflared tunnel --url http://localhost:3001
```

This prints a `https://<random>.trycloudflare.com` URL. Copy it — that is your `RELAY_URL`.

> The relay listens on port 3001 by default. Do not expose it directly to the internet; Cloudflare Tunnel adds TLS and DDoS protection.

## 5. Vercel Deployment

### Via Vercel Dashboard

1. Push your repository to GitHub
2. Go to [vercel.com](https://vercel.com) → Import Repository
3. Set all `.env.local` environment variables in Project Settings → Environment Variables
4. Deploy

### Via CLI

```bash
npx vercel --prod
```

Set environment variables:

```bash
npx vercel env add META_PAGE_ACCESS_TOKEN
```

Repeat for all variables listed in the `.env.local` table above.

## 6. Omada External Portal Configuration

In your Omada Controller, set the **External Portal URL** to:

```
https://<your-vercel-app>.vercel.app/portal
```

(For local testing, use your Cloudflare Tunnel URL or `http://localhost:3000/portal` via ngrok.)

**Important:** Ensure the controller is configured to forward the standard client context as query parameters. The portal requires `clientMac`, `apMac`, `ssid`, `site`, and `redirectUrl`.

**Example redirect URL generated by Omada:**

```
https://my-app.vercel.app/portal?clientMac=AA:BB:CC:DD:EE:FF&apMac=11:22:33:44:55:66&ssid=GuestWiFi&site=MainOffice&redirectUrl=https://google.com
```

If these parameters are missing or tampered with, the portal will reject the session creation request (400 Bad Request).

## Troubleshooting

| Symptom | Check |
|---------|-------|
| Portal doesn't load | Omada must forward `clientMac`, `apMac`, `ssid`, `site`, and `redirectUrl` as query parameters. Verify the External Portal URL format and that the controller firmware supports URL parameter passthrough. |
| "Follower count not increased yet" | This shouldn't happen in mock mode (150 > 1). Verify `MOCK_FOLLOWERS=true` in `.env.local`. If in real mode, ensure users are actually following the page between attempts. |
| Relay returns 401 | `RELAY_API_KEY` mismatch between `.env.local` and `local-relay/.env`. Check both files. |
| Relay returns "Relay unreachable" | The relay is not running. Start it: `cd local-relay && npm start`. |
| Session expires before verification | The session TTL is 10 minutes. Refresh the portal page to create a new session. |
| Omada login fails | Verify `OMADA_API_BASE`, `OMADA_USERNAME`, and `OMADA_PASSWORD` are correct. Some controllers use self-signed certificates — the relay uses Node.js native `fetch` which may reject them. Test with `curl` first. |
