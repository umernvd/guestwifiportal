# Project Reference: Facebook Follower-Gated WiFi Portal

## Overview

A captive portal proof-of-concept. Guests connect to a WiFi network, get redirected to a Vercel-hosted Next.js page, see a "Follow our Facebook page" button, and must follow the page to prove they're a real user. They then click a verify button; the backend checks Facebook's Graph API for follower count increase, and if it passes, authorizes the guest on the Omada controller via a local relay.

**Key constraints: no database, no separate backend, session state lives in an in-memory Map on Vercel.**

## Architecture

```
Guest Browser
     │
     ▼  (redirected by Omada controller)
Vercel (Next.js App)
  ├── /portal/page.tsx              ← Client Component (follow + verify UI)
  ├── /api/portal/init              ← POST: create session
  ├── /api/portal/verify            ← POST: check follower count, trigger Omada
  ├── /api/session/[token]          ← GET: return session status
  ├── /api/graph/fan-count          ← GET: fetch Facebook follower count
  └── /api/omada/authorize          ← POST: bridge to relay (internal only)
     │
     │  via Cloudflare Tunnel
     ▼
Local Relay (Express.js on port 3001)
  └── /relay/omada-auth             ← POST: logs into Omada, authorizes client
     │
     ▼
Omada Controller (LAN-only)
```

## Complete End-to-End Flow

1. **Guest connects to WiFi** — Omada controller intercepts and redirects to `https://<vercel-url>.vercel.app/portal?clientMac=...&apMac=...&ssid=...&site=...`
2. **Portal page loads** (`app/portal/page.tsx`) — reads URL params, POSTs to `/api/portal/init`
3. **Session created** (`app/api/portal/init/route.ts`) — stores session with status `PENDING` and `initialFollowerCount: 0`, returns `{ token, expiresIn, redirectUrl }`
4. **Guest sees the portal** — two buttons: "Open Facebook Page" and "I have followed! Check my access"
5. **Guest follows the page** — taps the Facebook button, follows the page in a new tab, then taps verify
6. **Verify clicked** — POST to `/api/portal/verify` with `{ token }`
7. **Status → VERIFYING** (`app/api/portal/verify/route.ts`) — calls `/api/graph/fan-count` (server-side relative URL)
8. **Fan count compared** — if `currentCount > initialFollowerCount + 1`, session → `VERIFIED`, then calls `/api/omada/authorize` bridge (awaited), returns `{ success: true, status: "AUTHORIZING" }`. If count not increased, returns error (session stays `VERIFYING`, guest can retry).
9. **Omada bridge** (`app/api/omada/authorize/route.ts`) — sends raw MACs (`clientMac`, `apMac`, `ssid`, `site`) to relay via `RELAY_URL/relay/omada-auth`
10. **Relay** (`local-relay/index.js`) — in mock mode returns success immediately; in real mode logs into Omada controller and authorizes client via `extPortal/auth`
11. **Result returned** — bridge awaits relay response, updates session to `AUTHORIZED` (or `FAILED` with `failureReason`)
12. **Portal polls status** — client component polls `/api/session/[token]` every 3 seconds (only after verify click)
13. **On AUTHORIZED** — redirects the guest to their original destination
14. **On FAILED** — shows the failure reason; guest must reconnect WiFi to retry

## Session Data Model

Defined in `types/index.ts`:

| Field | Type | Description |
|-------|------|-------------|
| `id` | `string` | UUID v4 (generated by `crypto.randomUUID()`) — used as the token |
| `status` | enum | `PENDING` \| `VERIFYING` \| `VERIFIED` \| `AUTHORIZING` \| `AUTHORIZED` \| `FAILED` |
| `clientMac` | `string` | Client MAC address (from Omada redirect) |
| `apMac` | `string` | Access Point MAC address |
| `ssid` | `string` | WiFi network SSID |
| `site` | `string` | Omada site identifier |
| `redirectUrl` | `string` | Original destination URL the guest tried to reach |
| `initialFollowerCount` | `number` | Follower count at init time (always 0, threshold is `currentCount > 1`) |
| `verifiedAt` | `number?` | Timestamp when fan-count check passed |
| `failureReason` | `string?` | Error message if status is `FAILED` |
| `createdAt` | `number` | `Date.now()` at session creation |
| `expiresAt` | `number` | `createdAt + 10 * 60 * 1000` (10 minute TTL) |

## Session State Machine

```
PENDING ──(verify clicked)─▶ VERIFYING ──(fan count increased)─▶ VERIFIED ──(bridge called)─▶ AUTHORIZING ──(Omada ok)─▶ AUTHORIZED
                                                            │                                  │
                                                            │                                  └──(Omada fails)──▶ FAILED
                                                            │
                                                            └──(fan count NOT increased)──▶ stays VERIFYING (retry)
```

- Status transitions handled by `sessionStore.updateStatus(id, newStatus, meta?)`
- Expired sessions deleted by `setInterval(cleanupExpired, 30_000)`
- Once a session reaches `FAILED` or expires, the guest must reconnect WiFi to start over

## API Routes Reference

All routes in `app/api/` follow the `{ success: boolean, data?: any, error?: string }` response format.

| Method | Path | Purpose | Request | Response |
|--------|------|---------|---------|----------|
| POST | `/api/portal/init` | Create a session | `{ clientMac, apMac, ssid, site?, redirectUrl? }` | `{ token, expiresIn, redirectUrl }` |
| POST | `/api/portal/verify` | Check follower count, trigger Omada | `{ token }` | `{ status: "AUTHORIZING" }` or error |
| GET | `/api/session/[token]` | Poll session status | — | `{ status, expiresAt, failureReason }` |
| GET | `/api/graph/fan-count` | Fetch Facebook follower count | — | `{ count }` or error |
| POST | `/api/omada/authorize` | Bridge to relay (internal only) | `{ token }` | `{ success: true, data }` or error |

### Key route behaviors

- **`/api/portal/init` POST**: Only `clientMac`, `apMac`, `ssid` are required. Defaults `site` to `""` and `redirectUrl` to `"/"` if not provided. Returns a session `token` (UUID v4) — no code, no Facebook post URL.
- **`/api/portal/verify` POST**: Sets session → `VERIFYING`, calls `/api/graph/fan-count` via relative URL (`new URL("/api/graph/fan-count", request.url)`). Compares `currentCount > initialFollowerCount + 1`. If threshold met, session → `VERIFIED`, then calls `/api/omada/authorize` (awaited). Returns `{ success: true, status: "AUTHORIZING" }` on pass, `{ success: false, error }` on fail. If fan-count API is unreachable, session → `FAILED`.
- **`/api/graph/fan-count` GET**: If `MOCK_FOLLOWERS=true`, returns `{ success: true, count: 150 }`. Otherwise calls Facebook Graph API v20.0 `/{pageId}?fields=followers_count` with Bearer token from `META_PAGE_ACCESS_TOKEN`.
- **`/api/omada/authorize` POST**: Strictly internal. No CORS headers. Checks session is `VERIFIED`, updates to `AUTHORIZING`, calls relay with raw MACs only (never the token). On relay success → `AUTHORIZED`, on failure → `FAILED` with `failureReason`.
- **`/api/session/[token]` GET**: Returns current status. Used by portal page polling (3s interval, starts only after verify click).

## Environment Variables

6 variables in `.env.local` (Vercel-side). 6 variables in `local-relay/.env` (relay-side). Required vars are accessed directly from `process.env` — no programmatic validation at startup.

### `.env.local` (Vercel)

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `META_PAGE_ACCESS_TOKEN` | Yes | `mock` | Facebook Page Access Token (Graph API) |
| `META_PAGE_ID` | Yes | `mock` | Facebook Page ID |
| `RELAY_URL` | Yes | `http://localhost:3001` | Relay endpoint (Cloudflare Tunnel URL in production) |
| `RELAY_API_KEY` | Yes | `test123` | Shared secret for authenticating Vercel → Relay requests |
| `MOCK_FOLLOWERS` | No | `true` | Set to `true` to skip real Graph API calls (returns 150) |
| `NEXT_PUBLIC_FACEBOOK_PAGE_URL` | No | — | Public URL for the "Open Facebook Page" button |

### `local-relay/.env` (Relay)

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `MOCK_OMADA` | No | `true` | Set to `true` to skip real Omada calls (returns success) |
| `RELAY_API_KEY` | Yes | `test123` | Must match the value in `.env.local` |
| `OMADA_API_BASE` | No* | — | `https://{IP}:{PORT}/{CONTROLLER_ID}/api/v2/hotspot` |
| `OMADA_USERNAME` | No* | — | Omada operator username |
| `OMADA_PASSWORD` | No* | — | Omada operator password |
| `PORT` | No | `3001` | Relay listen port |

*Not required when `MOCK_OMADA=true`.

## Facebook Setup (Graph API)

To run with real follower counts:

1. Go to **developers.facebook.com** → Create or open a Business app.
2. Add the **Facebook Graph API** product.
3. Go to **Tools** → **Graph API Explorer**.
4. Select your app, select **Page Access Token** with `public_profile` and `pages_read_engagement` permissions.
5. Click "Generate Access Token" → copy the short-lived token, or extend to a permanent token via the docs.
6. Copy your Page ID from the Graph API Explorer response or your Page's **About** section.
7. Set `META_PAGE_ACCESS_TOKEN` and `META_PAGE_ID` in `.env.local`, and set `MOCK_FOLLOWERS=false`.

## Local Relay Reference

`local-relay/index.js` is a standalone Express.js server (port 3001 by default). It is a **stateless proxy** — no session awareness, no tokens. Each request is self-contained.

**Mock mode**: If `MOCK_OMADA=true`, the relay skips all Omada interaction and returns `{ success: true, mock: true }`. Only `RELAY_API_KEY` is required in this mode.

**POST `/relay/omada-auth`** (non-mock mode):
1. Validates `x-api-key` header against `RELAY_API_KEY` (401 if mismatch)
2. Validates body fields: `clientMac`, `apMac`, `ssid`, `site` (400 if missing)
3. **Step A**: `POST {OMADA_API_BASE}/login` with `{ name: OMADA_USERNAME, password: OMADA_PASSWORD }`
4. Extracts `Csrf-Token` from login response headers
5. **Step B**: `POST {OMADA_API_BASE}/extPortal/auth` with `Csrf-Token` header and body `{ cid: clientMac, ap: apMac, ssid, site, time: 86400 }`
6. Returns `{ success: true, data }` or appropriate error

Run with:
```bash
cd local-relay
npm start
```

## Security Measures

1. **No token leak to relay** — The relay receives only raw MACs (`clientMac`, `apMac`, `ssid`, `site`), never the session token. The token is resolved by the Vercel-side bridge route.
2. **No CORS on authorize route** — `/api/omada/authorize` has no `Access-Control-*` headers, blocking browser cross-origin requests.
3. **API key authentication** — Relay validates `x-api-key` on every request; Vercel stores the key as an env var.
4. **Secrets never in browser** — The only `NEXT_PUBLIC_*` env var is the Facebook page URL. All secrets stay server-side.
5. **`.env*` in `.gitignore`** — All `.env` files are gitignored. Env vars set via Vercel Dashboard for production.
6. **Process isolation** — Local relay is a separate Node process with its own `.env`, separate from the Next.js app.
7. **10-minute TTL** — Sessions auto-expire. `cleanupExpired()` runs every 30 seconds.

## Deployment Quick Reference

Full details in `DEPLOYMENT.md`.

1. **Set env vars** in Vercel Dashboard (all 6 `.env.local` variables)
2. **Deploy** via `npx vercel --prod` or GitHub import
3. **Start relay**: `cd local-relay && npm start` (or `pm2 start index.js --name omada-relay`)
4. **Expose relay**: `cloudflared tunnel --url http://localhost:3001` → copy HTTPS URL → paste as `RELAY_URL` in Vercel
5. **Configure Omada**: External Portal URL = `https://<vercel-url>.vercel.app/portal`

## Troubleshooting FAQ

| Symptom | Likely Cause |
|---------|-------------|
| Portal shows "Missing WiFi session parameters" | Omada controller not forwarding `clientMac`, `apMac`, `ssid` query params. Check External Portal URL format. |
| "Follower count not increased yet" | User hasn't actually followed the page. In mock mode, this shouldn't happen (150 > 1) — verify `MOCK_FOLLOWERS=true`. |
| "Relay unreachable" | Cloudflare Tunnel dropped. Restart `cloudflared tunnel --url http://localhost:3001`. |
| Relay returns 401 | `RELAY_API_KEY` mismatch between `.env.local` and `local-relay/.env`. |
| Omada login fails | Wrong `OMADA_API_BASE`, `OMADA_USERNAME`, or `OMADA_PASSWORD`. Test with `curl` in non-mock mode. |
| Session expires before verification | 10-minute TTL expired. Refresh the portal page to create a new session. |
| Internal fetch fails in verify route | The relative URL `/api/graph/fan-count` requires server-side fetch. Verify the request originates server-side. |
